# GITHUB_SETUP.md — как загрузить FoxFire Hub на GitHub с нуля

Эта инструкция — для полного новичка, который никогда не пользовался Git и GitHub.
Выполняй шаги по порядку, ничего не пропуская.

## Шаг 1. Установи Git

Если у тебя ещё нет Git — скачай и установи с https://git-scm.com/downloads
(next-next-next, ничего специально настраивать не нужно). Проверить, что всё
установилось, можно командой в терминале:

```bash
git --version
```

Если видишь номер версии (например `git version 2.44.0`) — всё в порядке.

## Шаг 2. Создай аккаунт и пустой репозиторий на GitHub

1. Зарегистрируйся на https://github.com, если ещё не зарегистрирован.
2. Нажми зелёную кнопку "New" (или открой https://github.com/new).
3. **Repository name** — например `foxfire-hub`.
4. Выбери **Public** (чтобы приложение могло само скачивать `registry.json` и
   `app-version.json` без пароля — это открытые файлы, ничего секретного в них нет).
5. **НЕ ставь галочки** "Add a README file", "Add .gitignore", "Choose a license" —
   они уже есть в папке проекта, если добавить их ещё раз на GitHub, будет конфликт.
6. Нажми "Create repository". Откроется пустая страница с инструкциями — они нам
   не нужны, используй шаги ниже.

## Шаг 3. Загрузи проект

Открой терминал внутри папки проекта (`streamer-helper-market` / `foxfire-hub`,
как ты её назвал) и выполни команды по очереди:

```bash
git init
git add .
git commit -m "Первая версия FoxFire Hub (альфа)"
git branch -M main
git remote add origin https://github.com/ТВОЙ_НИК/foxfire-hub.git
git push -u origin main
```

Замени `ТВОЙ_НИК` на свой ник на GitHub и `foxfire-hub` — на имя, которое ты дал
репозиторию на шаге 2. При первом `git push` GitHub попросит войти — следуй
подсказкам на экране (обычно это окно браузера или запрос токена вместо пароля).

Готово — открой страницу репозитория в браузере и убедись, что все файлы на месте.

## Шаг 4. Настрой ссылки внутри приложения

Открой `src/appConfig.ts` в проекте и замени:

- `REGISTRY_URL` — на raw-ссылку своего каталога виджетов (это ОТДЕЛЬНЫЙ репозиторий,
  подробности в `HOW_TO_PUBLISH_REGISTRY.md`);
- `APP_UPDATE_URL` — на raw-ссылку файла `app-version.json` (можно прямо в этом же
  репозитории `foxfire-hub`, в корне — как раз для этого положен шаблон
  `app-version.example.json`, переименуй его копию в `app-version.json` перед тем как класть в репозиторий).

"Raw-ссылка" — это ссылка на файл в виде голого текста, а не красивая страничка
GitHub. Получить её просто: открой файл на GitHub → кнопка "Raw" в правом верхнем
углу → скопируй адрес из адресной строки браузера.

Сохрани изменения, закоммить и запушь снова:

```bash
git add src/appConfig.ts
git commit -m "Настроил ссылки на registry.json и app-version.json"
git push
```

## Шаг 5. (Необязательно) Автосборка релизов через GitHub Actions

В проекте уже лежит готовый файл `.github/workflows/release.yml`. Он сам собирает
`.exe` (Windows), `.dmg`/`.app` (macOS) и `.deb`/`.AppImage` (Linux) и прикладывает
их к релизу на GitHub, как только ты создаёшь тег версии. Чтобы им воспользоваться:

```bash
git tag v0.1.0-alpha.1
git push origin v0.1.0-alpha.1
```

Открой вкладку **Actions** на странице репозитория на GitHub — там появится
запущенная сборка (займёт несколько минут на всех трёх системах). Когда она
закончится, зайди во вкладку **Releases** — там будет черновик релиза с готовыми
установщиками. Проверь его и нажми "Publish release".

Никакого специального сервера или платной подписки для этого не нужно — сборка
идёт на серверах GitHub бесплатно (для открытых репозиториев — без ограничений).

## Что дальше

- Каждый раз, когда меняешь код — `git add .`, `git commit -m "что изменил"`, `git push`.
- Чтобы обновить каталог виджетов — редактируешь только файлы в ДРУГОМ репозитории
  (registry.json и папку `widgets/`), пересборка `foxfire-hub` для этого не нужна.
- Чтобы объявить пользователям о новой версии приложения — обновляешь
  `app-version.json` в этом репозитории (см. README.md, раздел "Автопроверка
  обновлений приложения").
