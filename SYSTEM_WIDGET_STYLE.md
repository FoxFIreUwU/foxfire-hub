# SYSTEM_WIDGET_STYLE.md — Стандарт создания виджетов ("помогалок") для FoxFire Hub

Этот файл описывает, как должен быть устроен КАЖДЫЙ виджет, чтобы FoxFire Hub мог его
показать, установить, обновить, откатить на старую версию и корректно настроить.

## 1. Структура папки одного виджета в GitHub-репозитории

```
widgets/
  my-widget/
    widget.manifest.json     ← "паспорт" виджета (обязателен, см. раздел 2)
    README.md                 ← человекочитаемое описание для GitHub
    screenshots/                ← ВСЕ картинки из этой папки автоматически попадают
      01.png                      в галерею карточки виджета в приложении
      02.png
    index.html / компонент виджета
    Settings.tsx                 ← панель настроек виджета
```

Папка `screenshots/` — обязательная конвенция: приложение при открытии модалки виджета
запрашивает список файлов в этой папке через GitHub API (`contents` endpoint) и строит
из них галерею. Не нужно перечислять скриншоты вручную в манифесте — просто клади файлы
в эту папку по порядку (`01.png`, `02.png`...), первый файл используется как обложка
карточки, если `previewUrl` не указан отдельно.

## 2. widget.manifest.json — полная схема

```json
{
  "id": "chat-box-neon",
  "name": "Неоновый чат",
  "author": {
    "name": "TvoyNik",
    "url": "https://github.com/TvoyNik"
  },
  "rating": 92,
  "tags": ["OBS", "Chat", "Windows"],
  "shortDescription": "Оверлей чата с неоновой подсветкой ников.",
  "fullDescription": "Полное описание на несколько абзацев: как работает, какие есть режимы, известные ограничения и т.д. Показывается в модалке по кнопке «Показать полностью».",
  "previewUrl": "https://raw.githubusercontent.com/USER/REPO/main/widgets/chat-box-neon/screenshots/01.png",
  "configSchema": {
    "textColor": { "type": "color", "default": "#e2820a", "label": "Цвет текста" }
  },
  "minAppVersion": "0.1.0",
  "versions": [
    {
      "version": "1.2.0",
      "releaseDate": "2026-09-01",
      "downloadUrl": "https://github.com/USER/REPO/releases/download/chat-box-neon-v1.2.0/chat-box-neon.zip",
      "status": "stable",
      "statusMessage": "",
      "minAppVersion": "0.2.0"
    },
    {
      "version": "1.1.0",
      "releaseDate": "2026-06-14",
      "downloadUrl": "https://github.com/USER/REPO/releases/download/chat-box-neon-v1.1.0/chat-box-neon.zip",
      "status": "warning",
      "statusMessage": "Известна проблема с прозрачностью фона на Windows 11."
    },
    {
      "version": "1.0.0",
      "releaseDate": "2026-03-02",
      "downloadUrl": "https://github.com/USER/REPO/releases/download/chat-box-neon-v1.0.0/chat-box-neon.zip",
      "status": "unavailable",
      "statusMessage": "Несовместима с текущей версией FoxFire Hub, установка отключена."
    }
  ]
}
```

### Обязательные поля
- `id` — уникальный идентификатор (латиница, без пробелов), совпадает с именем папки.
- `name`, `author.name`, `rating` (0–100), `tags`.
- `shortDescription` — 1 короткая строка, показывается сразу на карточке.
- `fullDescription` — полный текст, скрыт за кнопкой "Показать полностью" в модалке.
- `versions` — массив версий, см. ниже. Должен содержать хотя бы одну версию.

### Необязательные поля
- `author.url` — ссылка на автора (GitHub/Telegram/сайт), делает имя автора кликабельным.
- `previewUrl` — явная обложка карточки; если не указан, берётся первый файл из
  `screenshots/`.
- `configSchema` — настройки виджета (`color`, `number`, `text`, `boolean`, `select`).
- `minAppVersion` / `maxAppVersion` — совместимость с версией самого FoxFire Hub, см.
  раздел 10 ниже.

## 3. Поле `versions[]` — архив версий и выбор пользователем

- Каждая версия — отдельный объект с `version`, `releaseDate`, `downloadUrl`, `status`.
- В модалке виджета пользователь видит список версий (не только последнюю) и может
  установить любую из них — это и есть "откат"/скачивание старых версий.
- Список сортируется по `releaseDate` от новых к старым; самая новая версия со
  `status: "stable"` предлагается по умолчанию на карточке.

## 4. Поле `status` — техобслуживание и аварийное отключение версий

Три возможных значения:

| `status` | Поведение в приложении |
|---|---|
| `"stable"` | Обычная установка, никаких предупреждений. |
| `"warning"` | Установка разрешена, но показывается жёлтый баннер с текстом из `statusMessage` ("может работать нестабильно"). Автор сам решает, когда снять пометку. |
| `"unavailable"` | Кнопка "Установить" для этой версии заблокирована, показывается красный баннер с `statusMessage` (например, "версия отозвана из-за критического бага"). Уже установленные у пользователей копии не удаляются — это касается только новых установок. |

Чтобы снять виджет/версию с раздачи на время техработ, автору достаточно поменять
`status` в `widget.manifest.json` (или сразу в общем `registry.json`) и запушить
изменение — пересборка приложения не нужна, это тот же принцип "живого" реестра, что и у
остального каталога.

## 5. Авторство

- Имя автора (`author.name`) всегда отображается на карточке виджета и в модалке.
- Если указан `author.url`, имя становится кликабельной ссылкой.
- Один и тот же человек может быть автором нескольких виджетов — отдельного профиля
  автора в MVP не делаем, просто одинаковое имя/ссылка в разных манифестах.

## 6. Обязательная изоляция стилей

- Все CSS-классы виджета — с уникальным префиксом (`chatboxneon-*`), чтобы не
  конфликтовать со стилями FoxFire Hub или других виджетов.
- Виджет не использует глобальные стили магазина напрямую.

## 7. Проброс настроек (config) и перенос между ПК

- Виджет получает текущие настройки через `config`, соответствующий его `configSchema`.
- Изменение в `Settings.tsx` сразу отражается в живом превью виджета.
- Все значения `config` каждого установленного виджета входят в **общий файл экспорта
  настроек FoxFire Hub** (см. ниже) — так пользователь переносит не только список
  установленных утилит, но и их точные настройки на новый компьютер.

## 8а. Обновление (с версии 0.1.4): реальное скачивание/удаление

Начиная с версии 0.1.4 FoxFire Hub реально скачивает `downloadUrl` версии и
распаковывает его на диск, а при удалении виджета реально стирает эти файлы —
подробности (какая Rust-команда за это отвечает, где хранится путь установки
и настройки) описаны в `SYSTEM_RULES.md`, раздел 8. Формат `widget.manifest.json`
и `registry.json` из этого файла не меняется — `downloadUrl` по-прежнему должен
вести на настоящий `.zip`-архив с содержимым папки виджета (см.
`HOW_TO_PUBLISH_REGISTRY.md`, раздел "Как публиковать реальные версии").

## 8б. Обновление (с версии 0.1.5): реальный запуск и настройки через URL

Начиная с версии 0.1.5 кнопка "Запустить" у установленного виджета реально
открывает его `index.html` — либо в отдельном окне FoxFire Hub, либо (через
кнопку "Скопировать ссылку для OBS" в модалке) как готовая `file://`-ссылка
для источника "Браузер" в OBS. Подробности механизма — `SYSTEM_RULES.md`,
раздел 10. Для автора виджета это значит одно важное правило:

- **Настройки виджет получает через query-параметры своего `index.html`**, а
  не через `postMessage` — читай их через `new URLSearchParams(window.location.search)`
  прямо в своём JS-коде. Имя параметра = ключ настройки в `configSchema`
  (например, полю `"textColor": { "type": "color", ... }` соответствует
  параметр `?textColor=%23e2820a`). Значения `boolean` приходят строками
  `"true"`/`"false"`, `number` — обычной строкой с числом, их нужно привести
  к нужному типу самому (`Number.parseInt(...)`, `params.get(...) !== "false"`
  и т.п.) — оба пробных виджета (`widgets/stream-timer/index.html`,
  `widgets/stream-clock/index.html`) делают именно так, можно использовать
  как образец.
- Обязательно ставь значение по умолчанию из `configSchema` как fallback
  (`params.get("textColor") || "#e2820a"`) — так виджет откроется корректно,
  даже если его запустили без параметров вовсе (например, вручную открыли
  файл в браузере для проверки).

## 8. Формат файла экспорта настроек (`foxfirehub-profile.json`)

Создаётся кнопкой "Экспортировать настройки" в разделе Настройки, импортируется кнопкой
"Импортировать настройки" там же.

```json
{
  "appVersion": "0.1.0",
  "exportedAt": "2026-09-24T12:00:00Z",
  "installPath": "D:/FoxFireHub/widgets",
  "widgets": [
    {
      "id": "chat-box-neon",
      "installedVersion": "1.2.0",
      "config": { "textColor": "#e2820a" }
    }
  ]
}
```

При импорте FoxFire Hub:
1. Читает `installPath` и предлагает пользователю подтвердить/поменять его.
2. Для каждого виджета из списка скачивает указанную `installedVersion` (если она всё
   ещё доступна — см. `status`) и применяет сохранённый `config`.
3. Если версия помечена `unavailable`, предлагает установить ближайшую доступную и
   предупреждает, что настройки могут не полностью совпасть.

## 9. registry.json — общий список всех виджетов

`registry.json` в корне GitHub-репозитория — массив манифестов (без вложенности
`versions`, чтобы файл оставался лёгким для быстрой загрузки списка каталога; полный
манифест с `versions` и `fullDescription` подгружается отдельно, когда пользователь
открывает конкретный виджет):

```json
[
  { "id": "chat-box-neon", "name": "Неоновый чат", "author": {"name": "TvoyNik"}, "rating": 92, "tags": ["OBS", "Chat"], "shortDescription": "...", "previewUrl": "..." }
]
```

## 10. Совместимость с версией приложения (`minAppVersion` / `maxAppVersion`)

FoxFire Hub сам знает свою текущую версию (константа `APP_VERSION` в `src/appConfig.ts`)
и умеет автоматически проверять, подходит ли она для установки конкретной версии
конкретного виджета — точно так же, как это уже сделано для поля `status` (раздел 4),
только проверку делает не автор вручную, а приложение само, сравнивая номера версий.

- Оба поля необязательные и работают независимо друг от друга:
  - `minAppVersion` — виджет требует FoxFire Hub НЕ СТАРШЕ указанной версии (например,
    виджету нужна функция, которой не было в старых версиях приложения).
  - `maxAppVersion` — виджет ещё НЕ обновлён под более новые версии приложения и может
    сломаться на них (используется редко, обычно временно, пока автор не выпустит апдейт).
- Если ни одно из полей не указано — виджет считается совместимым с любой версией
  FoxFire Hub, поведение как раньше.
- Поля можно указать в двух местах:
  1. На верхнем уровне `widget.manifest.json` — общее ограничение для всех версий виджета.
  2. Внутри конкретного объекта `versions[]` — переопределяет общее ограничение только
     для этой версии (например, версия `2.0.0` требует более новый FoxFire Hub, чем
     версия `1.x` того же виджета).
- Формат номера версии — такой же, как у `APP_VERSION`: `"1.2.0"` или, для более ранних
  стадий, `"0.1.0-alpha.1"` / `"0.1.0-beta.2"` / `"0.1.0-rc.1"` (по возрастанию
  "готовности": alpha → beta → rc → релиз без суффикса).

### Как это выглядит в приложении

Если версия FoxFire Hub, установленная у пользователя, не проходит проверку:
- на карточке виджета и в модалке кнопка "Установить" становится неактивной и меняет
  подпись на "Недоступно" / "Обнови FoxFire Hub";
- в модалке под выбором версии показывается жёлтый баннер с понятным текстом, например
  "Нужна версия FoxFire Hub не ниже 0.2.0 (сейчас установлена 0.1.0-alpha.1)";
- если у пользователя эта версия виджета УЖЕ установлена — блокировка не применяется,
  запустить уже стоящий виджет можно всегда, ограничение действует только на новую
  установку/переустановку.

Пересборка приложения для этого не нужна — как и у поля `status`, всё решается на лету
по данным из `registry.json` / `widget.manifest.json` и текущей версии приложения.
