# SYSTEM_RULES.md — Глобальные правила проекта "FoxFire Hub"

Название проекта: **FoxFire Hub**. Раньше в черновиках встречалось "Маркет помогалок для
стримеров" — это то же самое приложение, просто теперь у него есть имя и фирменный стиль
бренда FoxFire (см. SYSTEM_MAIN_APP.md).

Этот файл читает каждый агент (Claude или другой), который в будущем будет работать над этим проектом.
Он объясняет, как вести себя и на чём построено приложение.

## 1. Как общаться с пользователем

- Пользователь — новичок в программировании. НЕ используй профессиональный сленг без объяснений.
- Весь код пишется полностью, без сокращений и без комментариев вида `// добавь сюда сам` или `/* код компонента */`.
- После любых изменений — короткое объяснение простыми словами: что сделано и как это посмотреть/запустить.
- Файлы и папки создаются агентом самостоятельно, пользователь ничего руками не пишет.

## 2. Стек технологий

- **Оболочка (десктоп):** Tauri (Rust) — превращает веб-приложение в маленькое `.exe`/`.app`.
- **Интерфейс:** React + TypeScript, собирается через Vite.
- **Стили:** Tailwind CSS.
- **Иконки:** библиотека Lucide Icons (`lucide-react`).

## 3. Архитектура плагинов (виджетов)

- Полный список доступных виджетов НЕ хранится внутри приложения.
- Он подгружается динамически с GitHub из файла `registry.json` (сырой URL вида
  `https://raw.githubusercontent.com/USER/REPO/main/registry.json`).
- Каждая запись в `registry.json` — это манифест одного виджета (см. `SYSTEM_WIDGET_STYLE.md`).
- Это значит: чтобы добавить новый виджет в магазин, НЕ нужно пересобирать приложение —
  достаточно обновить `registry.json` на GitHub.

## 7. Текущая стадия проекта

Проект сейчас в стадии **альфа** (см. `APP_STAGE_LABEL` в `src/appConfig.ts`). С версии
0.1.5 все основные функции из README.md ("Что уже работает, а что пока заглушка")
работают по-настоящему, включая реальный запуск виджета по кнопке "Запустить" (раздел
10 ниже) — бейдж "альфа" остаётся, потому что часть более крупных задач (настоящее
самообновление приложения через Tauri Updater, отдельная программа-публикатор) ещё
не сделана, см. `NEXT_AGENT_TASK.md`. Меняя стадию на "BETA" или убирая бейдж совсем —
не забудь, что `APP_VERSION` в том же файле должен соответствовать реальной версии релиза.

## 5. Перенос настроек и путь установки (архитектурное решение)

- Синхронизация между компьютерами реализована через **локальный файл экспорта**
  (`foxfirehub-profile.json`, формат — в SYSTEM_WIDGET_STYLE.md), а не через облачный
  аккаунт. Это осознанный выбор для MVP: не нужен свой backend/сервер, всё работает
  офлайн, файл просто переносится на флешке/через облако пользователя.
  Если в будущем понадобится автоматическая синхронизация (по аналогии с аккаунтом
  Telegram ID в проекте FoxFire-бота), это отдельная задача — не путать с текущим MVP.
- Путь установки утилит задаётся пользователем в Настройках (по умолчанию — стандартная
  папка приложения) и сохраняется в том же файле экспорта.

## 8. Реальная установка/удаление виджетов и хранение настроек (с версии 0.1.4)

- Скачивание и удаление файлов виджета — настоящее, не заглушка: React-часть
  (`src/App.tsx`) вызывает через `invoke` две Rust-команды из
  `src-tauri/src/main.rs`: `download_and_extract_widget` (скачивает `downloadUrl`
  версии и распаковывает zip в папку виджета) и `remove_widget_dir` (стирает эту
  папку). Куда именно ставить — решает `src/utils/localState.ts`
  (`resolveWidgetInstallDir`): выбранный пользователем путь установки, а если
  он не выбран — подпапка `widgets/` в стандартной папке данных приложения.
- Всё локальное состояние (какие виджеты реально скачаны, какая у них версия,
  куда установлены, путь установки, и настройки — как активных, так и уже
  удалённых виджетов) хранится в одном файле `foxfire-state.json` в папке
  данных приложения (`src/utils/localState.ts`, функции `loadLocalState` /
  `saveLocalState`). Файл перезаписывается автоматически при каждой установке,
  удалении, смене пути установки и изменении любой настройки виджета —
  пользователю для этого ничего нажимать не нужно.
- Не путать `foxfire-state.json` с `foxfirehub-profile.json` (раздел 8 в
  `SYSTEM_WIDGET_STYLE.md`): второй создаётся вручную кнопкой "Экспортировать
  настройки" специально для переноса на другой компьютер, а первый — служебный,
  для одного этого компьютера, и пользователь его не открывает.
- Удаление виджета (кнопка "Удалить виджет" в модалке) — с выбором:
  - **"Удалить, сохранить настройки"** — файлы виджета стираются с диска, но
    его `config` остаётся в `foxfire-state.json`. При повторной установке
    этого же виджета настройки применяются автоматически, без участия
    пользователя.
  - **"Удалить полностью"** — стираются и файлы, и сохранённый `config`.
- Вкладка **"Загруженное"** в нижней навигации всегда показывает то, что
  реально стоит на диске сейчас (по `foxfire-state.json`), независимо от того,
  доступен ли в данный момент `registry.json` на GitHub.

## 9. Загрузка каталога виджетов: анимация и ошибка (с версии 0.1.4)

- Тестовые виджеты-заглушки из `src/data/mockWidgets.ts` больше НЕ
  показываются — этот файл в проекте оставлен только для примера структуры
  данных, `App.tsx` его не импортирует.
- Пока `registry.json` загружается — показывается анимация (пульсирующие
  карточки-скелетоны, компонент `WidgetGridSkeleton` в `App.tsx`).
- Если загрузить `registry.json` не удалось (нет интернета, ссылка ещё не
  настроена, битый JSON) — показывается жёлтый баннер с объяснением, а во
  вкладке "Моды" остаются видны ТОЛЬКО уже скачанные виджеты (по тому же
  `foxfire-state.json`). Установить новый виджет в этом случае нельзя, пока
  каталог снова не станет доступен.

## 10. Реальный запуск установленного виджета (с версии 0.1.5)

- Кнопка "Запустить" у уже установленного виджета (карточка и модалка) — не заглушка:
  React-часть вызывает функции из `src/utils/widgetLaunch.ts`.
- `launchInstalledWidget` открывает `index.html` виджета (путь берётся из `installDir`
  в `foxfire-state.json`, см. раздел 8) в отдельном окне самого FoxFire Hub —
  `WebviewWindow` из `@tauri-apps/api/window`, путь на диске превращается в ссылку
  через `convertFileSrc` (встроенный `asset://`-протокол Tauri, уже разрешён в
  `tauri.conf.json`). Если окно этого виджета уже открыто — повторный вызов просто
  показывает и фокусирует существующее окно вместо второго.
- Настройки виджета (`config` из `foxfire-state.json`) передаются НЕ через `postMessage`,
  а через query-параметры URL (`?textColor=...&fontSize=...`) — ровно так, как их уже
  читают оба пробных виджета в `foxfire-hub-widgets` через `URLSearchParams`. Это и есть
  договорённость для авторов виджетов, см. `SYSTEM_WIDGET_STYLE.md`, раздел 8а.
- Отдельно от запуска внутри приложения — кнопка "Скопировать ссылку для OBS" в модалке
  виджета (`copyWidgetObsLink`) кладёт в буфер обмена настоящую `file://`-ссылку на тот
  же `index.html` с теми же query-параметрами. Она нужна отдельно от `asset://`-ссылки,
  потому что OBS — отдельная программа со своим источником "Браузер", ей нужен обычный
  путь на диске, а не внутренний протокол приложения.
- Для этого в `tauri.conf.json` (allowlist) и `src-tauri/Cargo.toml` (features) включены
  права `window > create` (создание нового окна) и `clipboard > writeText`
  (копирование в буфер обмена) — без них оба сценария выше не заработают.

## 6. Правило для будущих агентов

Перед тем как менять дизайн или архитектуру — сначала прочитай `SYSTEM_MAIN_APP.md` и
`SYSTEM_WIDGET_STYLE.md`. Не изобретай новый визуальный стиль — строго следуй уже описанному
(тёмный геймерский UI, стеклянные карточки, фиолетовые акценты).
