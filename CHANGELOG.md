## [Unreleased] — готовится к 0.1.7

### Исправлено
- **Звук заставки обрывался на середине.** Раньше `<audio>` жил внутри карточки и
  глушился при её исчезновении (через 1.65 с из 4 с звука). Теперь звук — один
  общий объект `Audio` вне компонента, его никто не останавливает, а заставка
  держится до события `ended` (с запасным таймером, чтобы не зависнуть).
  Если звук выключен в настройках или заблокирован webview — заставка уходит
  через 2.2 с. Интерфейс проявляется только когда заставка начала исчезать.
- **Настройки виджетов не сохранялись.** Встроенная страница настроек присылает
  весь конфиг разом, а `handleConfigChange` вызывался по одному разу на поле по
  устаревшему состоянию из замыкания — выживало только последнее поле. Теперь
  состояние читается из `localStateRef`, а запись `foxfire-state.json`
  сериализована и склеивается (всегда пишется самая свежая версия).
- **Ссылка для OBS** больше не `asset.localhost`: копируется постоянная
  `file://` ссылка на `index.html` без параметров, а встроенной странице
  настроек Hub передаёт её в `__obsUrl`.

### Добавлено
- Новый звук заставки (`src/assets/foxfire-splash.mp3`, 4.03 с, пик на 1.0 с) и
  переработанная заставка: карточка с градиентной рамкой и мягким светом за ней,
  крупная иконка с двойным кольцом и лучиками на «ударе», полоса прогресса,
  синхронная со звуком, мини-эквалайзер, версия приложения и статус «Готово».
- Файл настроек виджета `config.js` в папке установки: Hub пишет его при каждом
  изменении настроек и после (пере)установки (`utils/widgetConfigFile.ts`), виджет
  читает его сам — ссылку в OBS больше не нужно менять после правки настроек.

### Изменено
- Вкладка «Загруженное» переделана: вместо списка слева и панели справа —
  полки по категориям («Плагины» / «Приложения», как в «Обзоре», но
  компактнее), а у каждой установленной утилиты своя широкая карточка:
  обложка, версия, автор, описание, папка установки и «пульт» из плиток —
  Запустить, Ссылка для OBS, Настроить, О виджете и отдельно справа Удалить
  (с выбором «сохранить настройки / удалить полностью» прямо на карточке).
  Вкладка теперь скроллится целиком, а поиск и теги из шапки фильтруют
  установленное (`src/components/DownloadedPanel.tsx`, `src/App.tsx`).
- Вкладка «Категории» больше не повторяет «Обзор»: теперь это два крупных
  блока-кнопки («Плагины» и «Приложения») со счётчиками. Нажатие открывает
  страницу категории со всем списком и кнопкой «← Категории». Повторное
  нажатие на «Категории» в нижней панели возвращает к блокам, а ссылки
  «Все плагины/Все приложения» в «Обзоре» сразу открывают нужную категорию
  (`src/components/Categories.tsx`, `src/App.tsx`, `src/components/Overview.tsx`).
- Нижняя навигация: убран круг вокруг выбранной вкладки — теперь активная
  вкладка просто подсвечивается (акцентный цвет иконки и подписи + мягкое
  свечение). Вкладка «Обзор» стала первой и открывается при запуске
  (`src/components/BottomNav.tsx`, `src/App.tsx`).
- Вкладка «Моды» показывает только плагины (`kind` не указан или `"plugin"`).
- «Кузница FoxFire» переименована в «Редактор». Окно теперь плавно появляется
  и плавно закрывается (`.forge-window` в `src/index.css`). Причина прежнего
  «мелькания» — принудительный переход окна ОС в полноэкранный режим при
  открытии; он убран (Редактор и так занимает всё окно Hub), а полноэкранный
  режим по-прежнему включается тумблером в «Оформление Hub».
- Кнопка выхода переехала из шапки в низ левой панели, под «Оформление Hub»,
  и называется «Выйти из Редактора» (Esc работает как раньше).
- Кнопка сворачивания списка стала «язычком» на границе левой панели по центру
  по высоте. Панель сворачивается плавно и не пропадает совсем, а остаётся
  узкой полоской с иконками «Оформление Hub» и «Выйти из Редактора».

### Исправлено
- Галерея скриншотов показывала только обложку: список из папки
  `widgets/<id>/screenshots` реально не запрашивался (работали только моки).
  Теперь Hub читает папку через GitHub Contents API (репозиторий и ветка
  берутся из `REGISTRY_URL`), сортирует файлы по номеру (`01.png`, `02.png`,
  `10.png`) и кэширует результат. Необязательное поле `screenshots` в манифесте
  позволяет задать список вручную и не ходить в API (лимит GitHub API без
  токена — 60 запросов в час). Клик по миниатюре переключает главный кадр,
  в полноэкранном просмотре появились стрелки ← → (см. `src/utils/screenshots.ts`).

### Добавлено
- Кнопка «Редактор» в нижней панели (справа, после разделителя): открывает окно
  Редактора из любой вкладки. Работает и без установленных плагинов — тогда
  доступно «Оформление Hub». Новое состояние `editorOpen` в `src/App.tsx`.
- Вкладка «Обзор» (`src/components/Overview.tsx`) с тремя разделами:
  **Плагины** (HTML-дополнения для OBS и похожих программ по ссылке),
  **Приложения** (полноценные программы со своим .exe, `kind: "app"`) и
  **Игры** (на будущее, `kind: "game"`). Пока в каталоге нет приложений и игр,
  там показывается плашка «Скоро». Поиск и теги работают и в «Обзоре».
  Новое значение `"app"` у поля `kind` в манифесте (`src/types/widget.ts`).
- Живое обновление уже запущенного окна виджета: при любом изменении настройки
  (из автоформы или из `settingsEntry`) Hub рассылает Tauri-событие
  `foxfirehub:config-updated` с `{ widgetId, key, value }` — раньше окно
  виджета, открытое кнопкой "Запустить", подхватывало новые настройки только
  при перезапуске (см. `src/App.tsx` → `handleConfigChange`,
  `src/utils/embeddedSettings.ts` → `LIVE_CONFIG_UPDATE_EVENT`). Слушать
  событие необязательно, ничего не ломает для виджетов, которые его не знают.
- Необязательный снимок темы Hub (`__hubTheme`) в query-параметрах, которые
  Hub передаёт `settingsEntry` (`WidgetSettingsPanel.tsx`) и окну виджета при
  запуске (`launchInstalledWidget`) — акцентный цвет/скругление/масштаб
  текста/тема, выбранные пользователем в разделе "Внешний вид"
  (`src/utils/appearance.ts` → `themeBridgeSnapshot`). Осознанно НЕ передаётся
  в ссылку для OBS (`copyWidgetObsLink`) — она уходит зрителям, личная тема
  Hub стримера там ни при чём.
- `foxfirehub-bridge.js` — общий вспомогательный скрипт для авторов виджетов
  (живёт в папке каждого виджета, копируется как шаблон, не часть сборки
  самого Hub): чтение конфига из query-параметров, подписка на живые
  обновления, сохранение через `postMessage`, работа с `__hubTheme`. Контракт
  — `SYSTEM_WIDGET_STYLE.md`, раздел 11а. Ничего из раздела 11а не обязательно
  для уже существующих виджетов.
- Виджет `unified-chat` подключил `foxfirehub-bridge.js`: `index.html` теперь
  живо обновляется, пока запущен отдельным окном, а `settings.html` подхватывает
  акцентный цвет темы Hub для своих вкладок/кнопок (с фолбэком на фирменный
  `#e2820a`, если темы нет). Цвета самой ленты чата (роли, бейджи, фон
  карточки) по-прежнему настраиваются отдельно и с темой Hub не связаны.
- Заставка запуска (`SplashScreen.tsx`) полностью переделана: вместо
  пульсирующей иконки-плейсхолдера — покадровая анимация (иконка Hub из
  `icon.ico`, мягкое свечение, кольцевой импульс, зелёный индикатор),
  тайминг которой разобран вручную под конкретный звук
  (`src/assets/foxfire-appear.mp3`, огибающая громкости проверена через
  ffmpeg). Пик визуального эффекта совпадает с пиком звука (1.08с). Громкость
  занижена на двух уровнях — сам файл сведён на −6дБ от исходника, плюс
  плеер по умолчанию на 55% — исходник был почти впритык к 0дБ, на полной
  системной громкости это било бы по ушам. Новый переключатель "Звук при
  запуске" в разделе "Внешний вид" (`AppearanceSettings.tsx` →
  `settings.splashSound`, по умолчанию включён) позволяет отключить насовсем.
  Добавлен `src/vite-env.d.ts` (стандартный для Vite-проектов, почему-то
  отсутствовал) — нужен для типов при импорте `.mp3` как ассета.

## [[0.1.6] — 2026-09-27]

### Добавлено
- Новое поле `settingsEntry` в `widget.manifest.json` (на верхнем уровне и/или
  на уровне конкретной версии в `versions[]`, по аналогии с `minAppVersion`) —
  позволяет автору виджета подключить собственную встроенную страницу
  настроек вместо автоформы по `configSchema`. Контракт — `SYSTEM_WIDGET_STYLE.md`,

  вкладке "Загруженное", в `<iframe>` — без отдельного окна ОС. Обмен данными
  идёт через `window.postMessage` (`type: "foxfirehub:settings-saved"`), а не
  через Tauri-событие.
- `src/utils/embeddedSettings.ts` — разрешение `settingsEntry` для установленной
  версии виджета и проверка формата входящих сообщений.
- `src/components/DownloadedPanel.tsx` и `src/components/WidgetSettingsPanel.tsx` —
  новый вид вкладки "Загруженное": список установленных виджетов слева, панель
  настроек выбранного справа.
- `src/components/AutoSettingsForm.tsx` — старая автоформа по `configSchema`,
  вынесена в отдельный компонент, используется теперь и в новой панели настроек.
- Добавлена простая анимация загрузки

### Изменено
- Настройки виджета убраны из модалки установки (`WidgetModal.tsx`, раздел
  "Моды"/карточки) — она теперь отвечает только за установку, выбор версии,
  архив версий и удаление. Вместо блока настроек — подсказка со ссылкой на
  вкладку "Загруженное".
- Виджет `unified-chat`, версия `2.0.0` — `settings.html` теперь подключён
  как `settingsEntry` и умеет сохранять настройки живьём через `postMessage`
  в FoxFire Hub (раньше требовалось открытие в отдельном окне через Tauri-событие,
  оставлено как запасной вариант). Версия `1.0.0` того же виджета `settingsEntry`
  не объявляет и по-прежнему получает автоформу — пример разделения поддержки
  функции между версиями одного виджета.

## Локальный сервер для OBS и чтение чата YouTube без ключа
- `src-tauri/src/local_server.rs`: сервер на 127.0.0.1:47821–47830, раздаёт `/w/<id>/…`, отдаёт `/api/yt/poll`.
- `src-tauri/src/youtube_chat.rs`: чтение live-чата YouTube без API-ключа (неофициально).
- Ссылка для OBS теперь `http://127.0.0.1:порт/w/<id>/index.html?view=obs`; окно виджета тоже открывается по ней (fallback — asset.localhost).
- Новые зависимости: regex, tokio (time), tiny_http, reqwest+json.
