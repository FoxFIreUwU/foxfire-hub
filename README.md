# FoxFire Hub — маркет помогалок для стримеров

**Статус: альфа-версия (0.1.5).** Это ещё не финальный продукт — интерфейс и
архитектура уже рабочие, но часть функций внутри пока заглушки для проверки UI
(см. раздел "Что уже работает, а что пока заглушка" ниже). Ниже — простая инструкция,
как всё запустить у себя на компьютере.

## Что уже работает, а что пока заглушка

Работает по-настоящему:
- Загрузка каталога виджетов из `registry.json` на GitHub, с анимацией загрузки
  и понятной ошибкой, если каталог сейчас недоступен (см. раздел ниже).
- **Реальное скачивание и удаление файлов виджета** — кнопка "Установить"
  реально скачивает и распаковывает архив, кнопка "Удалить виджет" реально
  стирает его файлы, с выбором "сохранить настройки" или "удалить полностью".
- **Вкладка "Загруженное"** — отдельный список уже скачанных виджетов.
- Постоянное хранение настроек и списка скачанного между запусками
  (`foxfire-state.json`, см. `SYSTEM_RULES.md`, раздел 8).
- Поиск, фильтры по тегам, архив версий с выбором и откатом, статусы `stable` /
  `warning` / `unavailable`.
- Проверка совместимости версии виджета с версией приложения (`minAppVersion` /
  `maxAppVersion`) — см. `SYSTEM_WIDGET_STYLE.md`, раздел 10.
- Автопроверка обновлений самого приложения при запуске (см. раздел ниже).
- Экспорт/импорт настроек в файл `foxfirehub-profile.json`, выбор пути установки
  (импорт теперь тоже реально скачивает файлы виджетов).
- **Реальный запуск установленного виджета** — кнопка "Запустить" открывает
  `index.html` виджета в отдельном окне самого FoxFire Hub и передаёт ему
  сохранённые настройки. В модалке виджета есть также кнопка "Скопировать
  ссылку для OBS" — она копирует в буфер обмена готовую `file://`-ссылку с
  теми же настройками, чтобы вставить её прямо в источник "Браузер" в OBS
  (подробнее — раздел "Как запустить виджет" ниже).

Пока заглушки не осталось — весь список выше работает по-настоящему.

## Что нужно установить один раз

1. **Node.js** (версия 18 или новее) — https://nodejs.org (просто скачать и установить, next-next-next).
2. **Rust** — https://www.rust-lang.org/tools/install (для Windows нужно ещё поставить "Microsoft C++ Build Tools",
   установщик Rust сам подскажет это и даст ссылку).

## Как запустить проект (в режиме разработки, с окном приложения)

Открой терминал/консоль внутри папки проекта (`streamer-helper-market`) и выполни по очереди:

```bash
npm install
npm run tauri dev
```

Первая команда скачает все нужные библиотеки (может занять пару минут).
Вторая — откроет окно приложения. Любое изменение в коде сразу же обновит окно.

## Как запустить только в браузере (без Tauri/Rust), для быстрой проверки дизайна

```bash
npm install
npm run dev
```

Откроется ссылка вида `http://localhost:1420` — открой её в браузере.

## Как собрать готовый .exe / .app файл

```bash
npm run tauri build
```

Готовый установщик появится в папке `src-tauri/target/release/bundle`.

## Про иконку приложения

Иконки уже лежат в `src-tauri/icons/` и подключены в `src-tauri/tauri.conf.json` — ничего
дополнительно генерировать не нужно. Если захочешь заменить их на свои — нужна любая
PNG-картинка 1024×1024, и одна команда пересоздаст все нужные размеры и форматы:

```bash
npm run tauri icon путь/к/твоей/картинке.png
```

## Как запустить виджет ("Запустить")

Когда виджет уже установлен, кнопка на карточке (и в модалке) превращается в
"Запустить" и делает одно из двух — в зависимости от того, где ты хочешь его
использовать:

1. **Внутри FoxFire Hub** — просто нажми "Запустить". Откроется отдельное
   окно приложения с виджетом внутри, ему сразу передаются сохранённые
   настройки (цвет, размер шрифта и т.д. — что настроено в модалке виджета).
   Если окно этого виджета уже открыто — повторное нажатие просто вернёт
   фокус на него, а не откроет второе.
2. **В OBS (источник "Браузер")** — открой модалку виджета и нажми
   "Скопировать ссылку для OBS". В буфер обмена скопируется обычная ссылка
   вида `file:///C:/.../widgets/stream-timer/index.html?textColor=%23e2820a&fontSize=64`
   — вставь её в поле "URL" источника "Браузер" в OBS, и всё готово. Ссылка
   уже содержит все текущие настройки виджета в виде параметров адреса,
   ровно так же, как их читает `index.html` самого виджета.

Оба способа ведут на один и тот же файл на диске (`installDir/index.html` из
`foxfire-state.json`) — просто первый открывает его окном самого приложения
(для быстрой проверки, без OBS под рукой), а второй даёт ссылку, которую
понимает OBS.

## Структура проекта

```
streamer-helper-market/
  SYSTEM_RULES.md            ← общие правила проекта
  SYSTEM_MAIN_APP.md         ← дизайн-система оболочки магазина
  SYSTEM_WIDGET_STYLE.md     ← стандарт для создания новых виджетов
  GITHUB_SETUP.md            ← как загрузить этот репозиторий на GitHub с нуля
  HOW_TO_PUBLISH_REGISTRY.md ← как опубликовать свой каталог виджетов (registry.json)
  CHANGELOG.md               ← список изменений по версиям
  app-version.example.json   ← шаблон файла для автопроверки обновлений приложения
  src/
    appConfig.ts             ← версия приложения, ссылки на registry.json и на проверку обновлений
    App.tsx                  ← главный экран (весь магазин собирается здесь)
    types/widget.ts          ← описание структуры данных виджета
    data/mockWidgets.ts      ← тестовые виджеты (пока нет своего registry.json)
    utils/
      semver.ts                ← сравнение версий (1.2.0, 0.1.0-alpha.1 и т.д.)
      compatibility.ts         ← проверка "подходит ли версия приложения для виджета"
      appUpdate.ts             ← запрос app-version.json и решение, показывать ли баннер
      localState.ts            ← постоянное локальное состояние: что скачано, путь установки, настройки
      widgetInstall.ts         ← вызовы Rust-команд реального скачивания/удаления файлов виджета
      widgetLaunch.ts           ← реальный запуск установленного виджета (окно приложения) и ссылка для OBS
    components/
      Header.tsx              ← шапка с поиском и фильтрами
      UpdateBanner.tsx         ← баннер "Доступна новая версия"
      WidgetCard.tsx           ← карточка одного виджета в сетке
      WidgetModal.tsx          ← окно с деталями и настройками виджета
      BottomNav.tsx            ← нижняя панель навигации
  src-tauri/                 ← Rust-часть, превращающая сайт в десктопное приложение
```

## Как добавить свой список виджетов вместо тестовых

1. Создай публичный репозиторий на GitHub, положи туда файл `registry.json`
   (формат описан в `SYSTEM_WIDGET_STYLE.md`). Подробная пошаговая инструкция,
   включая два готовых пробных виджета, — в `HOW_TO_PUBLISH_REGISTRY.md`.
2. Открой `src/appConfig.ts`, найди строку с `REGISTRY_URL` и вставь туда прямую (raw) ссылку на свой файл.
3. Перезапусти приложение — оно само подтянет список виджетов оттуда, тестовые данные больше не понадобятся.

## Автопроверка обновлений приложения

Приложение при каждом запуске (и затем раз в несколько часов) само проверяет, не вышла
ли новая версия FoxFire Hub, и показывает баннер со ссылкой на скачивание, если да.

1. Открой `src/appConfig.ts` и вставь свою raw-ссылку в `APP_UPDATE_URL` — она должна
   вести на файл в формате `app-version.example.json` (переименуй копию в
   `app-version.json` и положи в свой репозиторий, например в корень).
2. Когда выпускаешь новую версию — обнови число в поле `latestVersion` этого файла
   на GitHub (и, если нужно, `minSupportedVersion`) и запушь изменение. Пересборка
   приложения для этого не нужна — это подтянется само, как и `registry.json`.
3. Не забудь при каждом релизе поднимать `APP_VERSION` в `src/appConfig.ts` (и
   версию в `package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml`
   — все четыре места должны совпадать).
